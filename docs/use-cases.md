# Основные юзкейсы (что система обязана поддерживать)

Список живой: сюда добавляем юзкейсы, которые для нас важны, вместе с тем, что нужно изменить в системе, чтобы их поддержать. Позже добавятся
юзкейсы ShadowJet. Связанные доки: [clients-and-flight-modes.md](clients-and-flight-modes.md), [persons-pilots.md](persons-pilots.md),
[users.md](users.md), [busy-birds.md](busy-birds.md).

## 0. Исходные понятия (современная дата-модель)

- **User** — вход в систему: токен (файл пользователя), `person.id`, `vatsim.cid`.
- **Person (пилот)** — состояние (`Idle`, `OnDuty`, `Resting`, `Travelling`) и локация (тип + id, пока аэропорт). Летает только `Idle` пилот в
  аэропорту; на время рейса он `OnDuty`, после посадки его локация — аэропорт посадки. Вердикт по пилоту — `status2.pilot.state`
  (`OK`, `NO_PERSON`, `PERSON_NOT_IDLE`, `PERSON_NOT_AT_AIRPORT`, `WRONG_AIRPORT`, `UNKNOWN`), в блокирующих состояниях действия дашборда дают 403.
- **Режим выполнения рейса** (кто выполняет шаги Blocks Off, Takeoff, Landing, Blocks On):
  - **автоматический, через SimTracker** — симулятор шлёт позреп раз в 10 секунд (G7 FlightBag), шаги определяются сами, оплата полная;
  - **ручной (manual)** — шаги нажимаются кнопками, трекинга нет; оплата другая (ориентир 10%), но оплаты **вне этого этапа** (см. ниже).
- **Режим выбирается в момент Start Flight и дальше не меняется.** Переключиться между режимами внутри рейса нельзя (ручной рейс нельзя
  «подхватить» трекером и наоборот). Режим относится к плечу (рейсу), не к миссии целиком: следующее плечо начинается новым Start Flight.
- **Дашборд** — `flight-dashboard.html` (веб) и вкладка Airways в G7 FlightBag. Кнопки им выдаёт сервер: `status2.mode` и `status2.actions`.

## 1. Юзкейс 1: BusyBirds через G7, автоматический режим

1. Пользователь входит в G7 (Airways-вкладка), токен стоит, пилот `Idle` в аэропорту, самолёт загружен в этом же аэропорту.
2. В G7 выбирает миссию BusyBirds, строит план, бронирует (Book). Рейсы создаются на пользователя.
3. В G7 нажимает **Start Flight**. Рейс начинается в **автоматическом режиме** (`TrackedViaTracker`): все следующие шаги — по позрепам.
4. Выполняет полёт (в разработке без симулятора: сценарные stubbed posreps `?stubbed-posreps`). Blocks Off, Takeoff, Landing, Blocks On
   определяет трекер; Start Boarding, Start Deboarding, Finish Flight нажимает пользователь.
5. Запись в логбуке (время, ночное, IFR), локация пилота — аэропорт посадки. Оплата пилота — отдельный этап (см. ниже).

**Паритет с вебом.** Параллельно открытый `flight-dashboard.html` в этом режиме показывает то же самое, что и G7, и позволяет выполнить
те же действия: не больше и не меньше (Start Flight / Start Boarding / Start Deboarding / Finish Flight по `status.actions`; остальные шаги —
«tracked automatically»; блокировка кнопок по состоянию пилота).

## 2. Юзкейс 2: BusyBirds через веб-страницу, ручной режим (и варианты)

1. Пользователь открывает `busy-birds.html`. Страница **учитывает пилота**: пользователь без персоны, неподходящее состояние пилота или пилот
   не в аэропорту — полёты не бронируются, причина показана; самолёты и миссии предлагаются соответствующие локации пилота (аэропорт персоны).
2. Букает любой самолёт, который стоит в аэропорту пилота (Book = диспетч рейсов). Страница переводит пользователя во Flight Dashboard.
3. Режим определяется кнопкой Start Flight:
   - **2а. Старт в веб-дашборде** — рейс **ручной**. Дальше все шаги кнопками (landing не раньше 75% плановой длительности после взлёта),
     перейти на SimTracker нельзя, даже если G7 открыт и шлёт позрепы (позреп для этого рейса игнорируется).
   - **2б. Рейс забукан на вебе, но Start Flight нажат в G7** — рейс **автоматический**, как в юзкейсе 1.
4. Следующие плечи плана выбирают режим заново своим Start Flight.

**Правило выбора режима при Start Flight (решение).** Выбор остаётся за пользователем. Веб-дашборд показывает статус позрепов (идут ли они
от G7) и, пока они идут, предлагает **обе** кнопки: **Start tracked flight** (автоматический режим, с проверками позиции самолёта) и
**Start manual flight** (ручной, без проверок). Если позрепов нет, доступен только ручной старт. G7 предлагает только
автоматический старт. Как это будет жить на практике, пока непонятно: начинаем с такого явного выбора и смотрим.

## 4. Открытые вопросы

1. **Ночное время и IFR в ручном режиме.** Трекер считает их по позрепам, в ручном рейсе позрепов нет. Варианты: писать ноль; считать по плановому маршруту и времени; не писать вовсе.
2. **Как будет жить выбор tracked / manual в вебе при идущих позрепах** — пока непонятно; начинаем с явного выбора пользователя и смотрим.
3. **Миссия BusyBirds начинается не с локации пилота.** Если journey в одном городе, а самолёт/пилот в другом, план начинается с перегонного (ferry) плеча. Принимаем ли пилота в качестве исходной точки плана (самолёт должен стоять там же)?
4. **Ручной рейс забукан, трекер подключён.** Что видит G7: рейс как чужой (информационно) или не видит совсем.
5. **Оплата** (отдельный этап): где хранить обещанные суммы, от чего считать 10% в ручном режиме.
