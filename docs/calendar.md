# Календарь рейсов пилота (подписка по ссылке)

Статус на 2026-11-09: сделано в коде, не выложено. Вне плана недели, делается по просьбе пользователя. Пилот подписывается на свои рейсы в Google Calendar (или любом другом)
по ссылке на файл iCalendar (`.ics`). Календарь сам перечитывает файл (Google раз в несколько часов), поэтому изменения рейсов доходят с задержкой.

## Ссылка

`https://<сервер>/calendar/<sqids id пользователя>-<ключ>.ics`, без авторизации: ссылка сама и есть ключ.

- `<ключ>` это первые 16 байт `HMAC-SHA256(секрет сервера, "calendar:" + id пользователя)` в hex (32 символа). Id пользователя прячется в Sqids (`Id.encode`, тот же алфавит, что у остальных id).
  Sqids только маскирует, защищает ключ.
- Ничего не хранится по пользователю: ссылка всегда считается заново и всегда одна и та же, пока не поменялся секрет.
- Неверная ссылка и отсутствие секрета дают одинаковый `404`.
- Токен пилота в ссылку не кладётся (ссылки на календари утекают, токен даёт доступ ко всему).

## Секрет

- Один файл `./calendar/secret.txt` (рядом с `world-data`), 32 случайных байта в hex; папка меняется системным свойством `airways.calendar.folder`; в git не попадает (`/calendar/`).
- **Сам не создаётся.** Пока файла нет, ссылки не работают (`slugOf` пусто, пилоту `503`). Создаёт и заменяет секрет только админ:
  `POST /admin/calendar/regenerate-secret` (временный файл и перенос поверх; если запись не удалась, остаётся старый секрет, `500`). **После перегенерации все выданные ссылки перестают работать**,
  пилоты должны скопировать новые. Сам секрет нигде не показывается и не логируется.
- Файл с неверным содержимым не заменяется сам (ошибка в логе, ссылки не работают), админ решает.
- Файл стоит копировать вместе с `world-data` при переезде сервера.

## Кто как получает ссылку

- Пилот: кнопка **Copy calendar link** на `pilot-roster.html` рядом с Reload; `GET /pilot/calendar-link` (токен пользователя) отдаёт путь, страница добавляет адрес сервера. Секрета нет: `503`, кнопка пишет «not available yet».
- Админ: `GET /admin/calendar/user/{id}/link` отдаёт путь для любого пользователя (`404` нет пользователя, `409` нет секрета).

## Содержимое файла

Один `VEVENT` на каждый рейс из прогноза ростера (`RosterForecast.of`: рейсы пилота, не завершённые и не отменённые, с ожидаемыми временами вылета и прилёта, то есть с учётом задержек
и конфликтов). UID `flight-<id>@airways.simforge.net` стабилен, календарь обновляет событие, а не дублирует его; завершённый или отменённый рейс из файла пропадает. Заголовок
«ICAO → ICAO», место: аэропорт вылета, описание: борт, статус рейса и ссылка на дашборд. Время в UTC (мировое время равно реальному). Подсказки `REFRESH-INTERVAL` и `X-PUBLISHED-TTL` один час.

## Код

`app/pblc/CalendarKeys` (секрет, ссылки), `CalendarFeed` (текст iCalendar: CRLF, свёртка строк по 75 октетов, экранирование), `CalendarController` (`GET /calendar/{slug}`),
`app/admin/CalendarAdminController`, `PilotController.getCalendarLink`; тесты `CalendarKeysTest`, `CalendarFeedTest`.

## Не сделано

- Перевозки пилота и журни в календарь не попадают (только рейсы ростера).
- Проверка подписки в самом Google Calendar на проде (нужен рабочий HTTPS-адрес сервера).
