## Список иконок и четыре флага

Иконки это 32x32 иконки FatCow на сайте (`fatcow/FatCow_Icons32x32/`), у веба есть и 16x16 (`FatCow_Icons16x16/`). У каждой иконки четыре **независимых** флага (не один вид,
иконка может быть сразу несколькими):

| Флаг | Смысл |
|---|---|
| `forbidden` | иконка нигде не показывается, даже тому, кто её выбрал (иконки действий вроде `user_add.png`, ненужные картинки); перекрывает остальные флаги, но они сохраняются |
| `common` | иконку можно выдать пассажиру случайно |
| `pilot` | пилот может выбрать её себе |
| `special` | для особых журни (Дарт Вейдер и сопровождающие, пункт 23 бэклога) |

- Пилот, который уже выбрал иконку, сохраняет её, даже когда флаг `pilot` снят (иконка исчезает только из списка выбора); `forbidden` её скрывает.
- Номер иконки (`avatarId` персоны) это номер строки (первая после заголовка 1, 0 «без аватарки»). Строки не двигают и не удаляют, новые добавляют в конец.
- Умолчания для иконки без значения в колонке: не `forbidden` значит `common` и `pilot`, не `special`; `forbidden` значит ни то, ни другое, ни третье.

Код: `tools/AvatarList` (список, флаги, чтение и запись файла), `tools/Avatars` (единственный экземпляр сервера и короткие вопросы игры: `allowedFiles` = что может выбрать
пилот, `commonFiles` = пул случайных пассажиров, `specialFiles`, `idOfAllowedFile`, `shownFile`).

## Файл

- Живой файл `./avatars/avatars.csv` (относительно рабочей директории приложения, рядом с `world-data`), **вне classpath**; папка задаётся системным свойством
  `airways.avatars.folder` (в тестах это папка, которой нет), в git не попадает (`/avatars/` в `.gitignore`).
- Колонки: `file,forbidden,common,pilot,special`, значения 0 и 1. Пока файла нет, список это затравка из ресурса `avatars.csv` (колонки `file,forbidden`, 159 иконок, шесть
  `forbidden`): так сейчас работает прод, файл создаст первое переключение.
- Каждое переключение флага переписывает файл целиком: временный файл `avatars.csv.tmp` и перенос поверх (атомарный, где поддерживается). Если файл записать не удалось,
  список в памяти не меняется и админка получает 500. Переключение, которое ничего не меняет, файл не трогает.
- Новые иконки добавляются в конец ресурса `avatars.csv`; при чтении они дописываются в конец живого списка с обычными флагами, если строки живого файла совпадают с
  началом ресурса по именам (иначе в лог пишется ошибка и новые не добавляются). Дописанное попадает в файл при следующем переключении.
- Живой файл не читается (ошибка чтения) — сервер не подменяет его затравкой, иначе следующее переключение затёрло бы настройки.

## Админка

- `GET /admin/avatars` весь список `[{id, file, forbidden, common, pilot, special}]` (в том числе `forbidden`).
- `POST /admin/avatars/flag?file=<имя>&flag=forbidden|common|pilot|special&value=true|false` меняет один флаг, отвечает строкой после изменения; `400` неизвестный флаг,
  `404` нет такой иконки (имя ровно как в списке, путь не пройдёт), `500` файл не записался.
- Страница `simforge-web/airways/admin/avatars.html`: все иконки с картинкой, номером, именем и четырьмя галочками, фильтр по имени, счётчики по флагам, `forbidden`-строки
  притушены. Токен админа берётся из браузера (как на карте `admin/map.html`). Галочка уходит на сервер сразу и показывает то, что ответил сервер; при ошибке она
  возвращается назад, строка краснеет.

## Аватарки пассажиров

- **Генератор** `world/computations/PassengerAvatars`, ничего не хранится: по id журни и размеру группы получается список аватарок, на каждого пассажира отдельная (группа из 4
  человек даёт 4). Зерно это id журни, пассажир номер k не зависит от размера группы. Инициалы две заглавные английские буквы. Иконка из пула `common` (`Avatars.commonFiles()`)
  выбирается по самому большому хешу от «зерно + имя файла» (не по индексу в списке): новая иконка в пуле меняет картинку только тем, кому она выпала, снятый флаг иконки только тем,
  у кого она была. Нет иконок в пуле: `user.png`. Хеши: SplitMix64 и FNV-1a. **Алгоритм после выпуска не меняется** (аватарки существующих журни изменились бы); значения закреплены в
  `PassengerAvatarsTest` (посчитаны независимой реализацией на Python).
- **Порядок на полоске:** ключ `seatKey(id транспортного рейса, id журни, номер пассажира)` (SplitMix64), пассажиры сортируются по ключу. Порядок случайный, воспроизводимый, журни не
  лежат подряд, и он не зависит от того, кто ещё на борту: при боардинге и дебоардинге остальные не меняют порядок.
- **Эндпоинт** `GET /flight-dashboard/passengers?flightId=` (пользователь, рейс должен быть его): `{count, passengers: [{kind, initials, icon}]}` в порядке полоски, `kind` равен `pax`
  (для перевозимых пилотов будет `pilot`), `icon` это имя файла. Это журни рейса в статусах «на борту» и «ждёт высадки» (`FlightDashboardController.buildPassengers`); рейс без
  транспортного рейса (ферри) и пустой самолёт дают пустой список. В общий `/status` не кладётся: клиент спрашивает список, когда меняются число на борту (`ponBrd`) или статус
  транспортного рейса (`tfSt`). Число на полоске может отличаться от `ponBrd` на одну группу: полоска идёт по журни, плитка по счётчику пассажиров.
- **Веб-дашборд** (`flight-dashboard.html`): полоса `On board` на всю ширину между плитками и областью этапа, показывается с боардинга до конца дебоардинга. Иконки родные 16x16 (папка
  `fatcow/FatCow_Icons16x16/`), без масштабирования. Пока они помещаются, лежат рядом (с зазором 2 пикселя), потом наезжают друг на друга не больше чем наполовину; когда их больше, ряд
  переходит на новую строку (в строке столько иконок, сколько помещается с наездом на половину). Инициалы по наведению мыши (и по касанию, исчезают сами), пилот рамкой. Стабы:
  `?stub=boarding`, `?stub=crowd` (220 пассажиров, три строки), `departure`, `flying` и др.
- **G7** (`AirwaysTab.js`, `FlightBag.html`, `FlightBag.css`): та же полоса под строкой «On board: N», иконки 32x32 (родные, `fatcow/FatCow_Icons32x32/` на `simforge.net`), тот же перенос на
  новые строки (наезд на половину, у 32 пикселей это 16), инициалы под рядом по наведению и по касанию. Запрос идёт с теми же ключами, что и остальные; после ошибки следующий не раньше
  чем через 15 секунд. В симуляторе не проверено.
