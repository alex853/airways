# Кэш ответов по отметкам изменений хранилищ

Статус: сделано для `/geo/countries`, `/geo/cities`, `/geo/airports` (закрыты три `todo ak0` «wrap the response into json and
keep that json in memory»). Так же можно кэшировать любые другие редко меняющиеся ответы.

## Идея

Ответ строится, сериализуется в JSON и сжимается **один раз**, затем отдаётся как есть, пока данные, от которых он
зависит, не менялись. Время жизни (TTL) и явная инвалидация из мест изменения не нужны: хранилища сами говорят, что они
менялись.

## Из чего состоит

- **`Storage.getLastChangedAtMillis()`** (`volatile long`). Выставляется при создании и загрузке хранилища и обновляется при
  любом изменении: `addRecord`, `deleteRecord`, любой `set`/`setUnsafe`, `reset`, `loadIfExists`. Каждое новое значение
  **строго больше** предыдущего (`max(часы, предыдущее + 1)`), поэтому два изменения в одну миллисекунду всё равно различимы.
  Отметка ставится **после** записи данных: кто увидел новое значение, увидит и новые данные. Неудавшиеся сеттеры (неверный
  тип, значение вне диапазона) отметку не меняют. Читается из любого потока без блокировок.
- **`getLastChangedAtMillis()`** проброшен наружу в `Cities`, `Airports`, `Countries`, `Airport2City`.
- **`WorldRunnerBean.getWorldForChangeStamps()`** возвращает мир без блокировки: только чтобы читать эти отметки (до загрузки
  мира `null`).
- **`ChangeTrackedCache<V>`** (`app/tools`): получает поставщика отметок (дешёвый, без блокировок) и билдер значения. `get()`
  возвращает кэшированное значение, пока отметки те же; при изменении пересобирает значение одним потоком, остальные ждут.
  Отметки читаются **до** сборки, так что изменение во время сборки приведёт к ещё одной сборке и устаревшее значение не
  останется.
- **`CachedJson`** (`app/tools`): готовый JSON (через `ObjectMapper` Spring, формат прежний) и его gzip. `toResponse(acceptEncoding)`
  отдаёт сжатый ответ (`Content-Encoding: gzip`, `Vary: Accept-Encoding`), если клиент принимает gzip и `q` не равен 0.
  Сжатие делается один раз при сборке, а не на каждый запрос (в проекте нет настроек сжатия Spring).

## От чего зависят ответы `GeoController`

| Ответ | Отметки |
|---|---|
| `/geo/countries` | `Countries` |
| `/geo/cities` | `Cities`, `Airport2City`, `Airports` |
| `/geo/airports` | `Airports`, `Airport2City`, `Cities`, `Countries` (страна аэропорта это страна самого населённого города связи) |

Запрос с актуальным кэшем **не берёт блокировку мира**. Сборка читает данные под read-lock мира, а сериализация и сжатие идут
вне блокировки. Кэш мапы `countryIdByAirportId` и `invalidateAirportCountries()` убраны: страна пересчитывается при каждой
сборке ответа (это один проход по связям), а сборка и так происходит только при изменении данных.

## Как добавить кэш для другого ответа

1. Определить хранилища, от которых зависит ответ, и дать их отметки в `Supplier<long[]>` (порядок важен, он фиксируется).
2. Билдер: прочитать данные под `worldBean.read(...)`, затем `CachedJson.of(objectMapper, данные)`.
3. В контроллере вернуть `cache.get().toResponse(acceptEncoding)`.
4. Если у зависимости нет `getLastChangedAtMillis()` (например, другой датамодели), добавить его по образцу `Cities`.
