# Журнал состояний G7 (`POST /g7/state-log`)

Инструмент G7 шлёт на сервер события своих состояний, сервер дописывает их строками в файлы. Ничего не вычисляется и не хранится в памяти. Код:
`app/pblc/G7StateLogController` (адрес, ответы) и `G7StateLog` (разбор и запись, тесты `G7StateLogTest`). Полный адрес на проде `https://d1.simforge.net:7776/g7/state-log`.

## Что приходит

Тело запроса это JSON. Клиент шлёт `Content-Type: text/plain;charset=UTF-8` (чтобы не было CORS preflight), поэтому тело разбирается как JSON независимо от
`Content-Type`.

```
{
  "app": "G7", "source": "DU2", "session": "k3x9ab-lq2f81", "dropped": 0,
  "events": [
    { "t": 1762500000123, "sim": 41234.5, "event": "fuel_start",
      "data": { "rawLeft": "1500.5", "rawRight": "1480", "gameState": 1, "onGround": true } }
  ]
}
```

- `app` всегда `"G7"`; `source` источник (сейчас `"DU2"`); `session` случайный id запуска инструмента (склеивает события одного запуска);
- `dropped` сколько событий клиент потерял с последнего успешного запроса (переполнялась очередь);
- `events` до 100 событий от клиента: `t` время клиента (мс), `sim` внутриигровое время (секунды), `event` имя события, `data` произвольный объект с плоскими значениями.

## Что делает сервер

На каждое событие одна строка JSON в файле дня. Папка `./g7/` рядом с `./world-data/` (относительно рабочей директории приложения; создаётся при записи, если её нет; в git
не попадает, `/g7/` в `.gitignore`). Файл `state-log-yyyy-MM-dd.jsonl`, день это день получения запроса по UTC. Порядок ключей в строке такой:

```
{"received":"2026-11-07T12:34:56.789Z","ip":"1.2.3.4","app":"G7","source":"DU2","session":"k3x9ab-lq2f81","t":1762500000123,"sim":41234.5,"event":"fuel_start","data":{...}}
```

- Лишние поля верхнего уровня и самого события игнорируются; если какого-то из полей нет, его нет и в строке; элемент `events`, который не объект, пропускается.
- Событий больше 200 в запросе: лишние отбрасываются (пишутся первые 200).
- Если `dropped` больше 0, перед событиями пишется отдельная строка `event: "client_dropped"`, `data: {"dropped": N}` (с теми же `received`, `ip`, `app`, `source`, `session`).
- `ip` это `getRemoteAddr()` запроса (за прокси это был бы адрес прокси; заголовки `X-Forwarded-*` не читаются).
- Запись одним вызовом на запрос под общей блокировкой, строки запросов не перемешиваются.

## Что отдаёт

| Код | Когда |
|---|---|
| `204 No Content` | всё записано (запрос без событий тоже 204, ничего не пишется) |
| `400` | тело не JSON или нет массива `events` |
| `413` | тело больше 64 КБ (проверяется по `Content-Length` и по прочитанным байтам) |
| `500` | файл не удалось записать (клиент повторит позже) |

Во всех ответах заголовок `Access-Control-Allow-Origin: *`. Ответ клиент не читает, ему важен только код 2xx (по нему он удаляет отправленные события из очереди, при другой
ошибке повторяет позже). Аутентификации и токенов нет (решено 2026-11-07, `AuthFilter` этот путь не проверяет), общий ключ не нужен.

## Reading the log

`GET /g7/state-log/read`, только чтение: те же строки JSON, как они записаны на диск (`text/plain`, одна строка на событие, без обёртки). Нет данных: `200` и пустое тело.
Токена и ключа нет (решено 2026-11-08), защита только ограничением частоты. Пример (Claude Code в репозитории G7 читает лог из консоли):

```
curl -s "https://d1.simforge.net:7776/g7/state-log/read?date=2026-11-08&event=fuel_,game_state"
```

Параметры (все необязательные):

| Параметр | Значение |
|---|---|
| `date` | `YYYY-MM-DD`, `yesterday` или `today`; по умолчанию сегодня (по UTC, как и файлы) |
| `from`, `to` | ISO-время (`2026-11-08T12:00:00Z` или со смещением), фильтр по времени получения (`received`) |
| `event` | префикс или список префиксов через запятую (`fuel_`, `fuel_,game_state,aircraftstate_,extpower_`) |
| `session` | id сессии точно |
| `limit` | число строк, по умолчанию 2000, максимум 20000 (больше обрезается до 20000) |
| `tail` | `1`: брать последние строки, а не первые |

Ответы: `200` (в том числе пустое тело), `400` (неверный параметр, коротко написано какой; такой запрос не считается в частоте), `429` (не более одного запроса в час с одного адреса,
заголовок `Retry-After` в секундах; отказ час не сдвигает), `500` (файл не прочитался). CORS-заголовка у чтения нет.

Безопасность: читается только файл дня, имя которого строится из проверенной даты (строгий формат `yyyy-MM-dd`, любые `/`, `..` и всё лишнее отклоняется), других путей и листинга
каталога нет. Адрес в ограничении это `getRemoteAddr()`: за прокси это адрес прокси, то есть один лимит на всех. Учтите, что в строках лога есть `ip` отправителя, а читать их может
любой, кто знает адрес (токена нет).
