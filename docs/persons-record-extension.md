# Persons: расширение записи персоны (32 → 40 байт)

Статус (2026-11-10): **шаг 1 выкачен на прод (`e21a8cda`, лог: `the second storage is made from the main one and checked field by field: 2 records, no differences`); шаг 2 (не пересоздавать, читать с диска и только проверять) написан в коде, не закоммичено, на проде нет**. Как расширять хранилища вообще: [storage-extension.md](storage-extension.md) (раздел «Если размер записи надо менять: второе хранилище»).
Код: `world/datamodel/Persons.java`, тесты `PersonsTest`.

**Зачем:** журни пилота (Travel «by airline», бэклог 19) нужна ссылка персоны на журни и флаги; в 32 байтах записи места нет (резервный байт и биты 12-13 initials мало, на ссылку
нужны 3 байта; флаг поездки один, он уместится в свободные биты initials, поэтому отдельного поля флагов нет, 5 байт резерва). Решено пользователем 2026-11-10: расширить запись, а не прятать значение в чужом поле по биту.

## Раскладка 40 байт (второе хранилище `persons2`)

Первые 32 байта это поля основного хранилища `persons` на тех же местах (`type`, `state`, `heartbeatTime`, `userId`, `locationType`, `locationId`, `originCityId`, `initials` с битами
`autoFinish` и `warpDrive`, резервный байт, `avatarId`, `bankAccountId`, `awakeCreditMinutes`, `creditTime`, `dutyStartTime`), потом новые:

| Поле | Тип | Байт | Смысл |
|---|---|---|---|
| `pilotJourneyId` | `Unsigned24bit` | 3 | журни пилота в поездке by airline, 0 нет |
| резерв | `Unsigned8bit` | 1 | может стать флагами; пока флаг у поездки один («выйти на ближайшей посадке»), он займёт свободный бит 12 в initials |
| резерв | `Signed32bit` | 4 | |

Индекс heartbeat `withHeartbeatIndex(2)` у второго хранилища тот же.

## Как устроено сейчас (шаг 2)

1. **Второе хранилище** `persons2` описано в `Persons` рядом с основным (имя файла `persons2`).
2. **Читается с диска как сохранено** (`loadIfExists`): основное из `persons`, второе из `persons2`, оно **больше не пересоздаётся** из основного (на шаге 1 пересоздавалось: `reset()`,
   `addRecord()` на каждый id и копирование по полям; код копирования удалён, он в истории коммита `e21a8cda`). Индекс heartbeat второго хранилища строится самой загрузкой файла.
3. **Проверка «поле в поле»** (`secondStorageMismatches`): после загрузки и при каждом сохранении. Сравниваются последний id, живые/удалённые записи и значения общих полей. Расхождение
   пишется в лог ошибкой (первые 20, строки вида `p/s #7 field 3 is 3 in persons and 99 in persons2`), **ничего не чинится**, мир идёт дальше, читается основное; успех пишется один раз при загрузке
   (`persons2 - the second storage is loaded from the disk and checked field by field: N records, no differences`, при расхождении `THE SECOND STORAGE DIFFERS FROM THE MAIN ONE AFTER THE LOAD
   (nothing is repaired)`). Отсутствующий файл `persons2` тоже расхождение (последний id 0 во втором).
4. **Мутаторы пишут в оба** (`Persons.create`, `deleteById`, все сеттеры `Person`, включая биты `autoFinish` и `warpDrive`): после изменения основного поля то же значение копируется во
   второе хранилище (`mirror`). Читается всё по-прежнему из основного.
5. **Мир сохраняет оба файла** (`Persons.save`): `persons` и `persons2`.

**Ограничения, о которых надо помнить:**
- **Новые поля (`pilotJourneyId`, резерв) пока не используются.** Они лежат только во втором хранилище, оно теперь читается с диска, значения в них переживают рестарт, но основное их не знает,
  а читается всё из основного. Использовать их можно только после свопа (шаг 6).
- **Если на шаге 2 вылезет расхождение, его не чинить кодом**: откатиться на шаг 1 (он пересоздаёт второе из основного) и разобраться.
- Персоны в игре не удаляются (только в тесте), поэтому оба хранилища выдают одинаковые id. Если бы основное переиспользовало id удалённой записи по карантину, второе дало бы другой
  id: это пишется в лог ошибкой (`THE SECOND STORAGE IS OUT OF STEP`), а проверка при сохранении покажет расхождение.

## Что дальше

6. **Выкатка шага 2**, несколько чистых рестартов, смотреть лог: `loaded from the disk and checked ... no differences` при каждой загрузке, ни одной ошибки при сохранениях. Потом **своп**:
   `persons2` становится основным (читается с диска, проверка против `persons` убирается), `persons` откладывается.
7. После нескольких рестартов старое хранилище удаляется из кода и с диска, файл `persons2` переименовывается в `persons` (или имя остаётся `persons2`, решить на месте).
8. Только после этого вводятся геттеры и сеттеры `pilotJourneyId` и бит «выйти на ближайшей посадке» (бит 12 в initials). Признак «пилот в поездке» это `pilotJourneyId != 0`, отдельный бит не нужен.

Перед выкладкой есть бэкап мира (`DiskStorageStrategy` кладёт прежний мир в `world-data/<name>.backup/<millis>`).
