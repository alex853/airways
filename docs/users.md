# Пользователи (user)

Пользователи хранятся в своём небольшом storage (`UserStorage`, `net.simforge.airways2.app.userstorage`), не в мире: токен проверяется на каждый
запрос пользователя, ему нельзя ждать блокировку мира. Пока не решено, будет ли сущность называться user или pilot (`User` помечен `todo ak2`).

## Хранилище (с 2026-11-06)

- Файл `./world-data/users/users` (рядом с данными мира, относительно рабочей директории приложения) и папки `./world-data/users.tmp` и `./world-data/users.backup/<время>`
  (тот же `DiskStorageStrategy`, что у мира: запись во временную папку, прежняя версия уходит в бэкап, лишние бэкапы прореживаются). Сохраняется сразу после каждого изменения.
- Запись 64 байта: заголовок удаления 1, `token` (`PlainString`, до 40 символов) 41, `personId` 3, `vatsimCid` 3, резерв 16.
- id пользователя это id записи (на него ссылаются рейсы `mission.getUserId()` и контексты SimTracker, он не меняется). Токены ищутся по индексу в памяти.
- `token` буквы и цифры, 10-40 символов, уникален; `personId` (персона пилота в `persons` мира, 0 значит «персоны нет», см. [persons-pilots.md](persons-pilots.md))
  и `vatsimCid` (0 неизвестен) от 0 до 16 777 215.
- Регистрация и управление в коде: `create(token, personId, vatsimCid)`, `setToken`, `setPersonId`, `setVatsimCid`, `all()`, поиск `findById`, `findByToken`.
  Эндпоинтов регистрации пока нет. В логе `User storage - u/s # - ...`, токены в лог не пишутся.
- **Временная миграция:** при первом старте, если storage пуст, пользователи один раз импортируются из прежних файлов `./users/user-<id>.cfg` (`token`,
  `person.id`, `vatsim.cid`, id берётся из имени файла и сохраняется; `last.location.airport` игнорируется). Сами файлы не меняются. После первого старта на
  проде удалить `LegacyUsersImport` и `importLegacyUsers` в `UserStorage`.

## Где используется

- `UserService.findUserIdByToken` (используется `AuthFilter` для `/busy-birds`, `/flight-dashboard`, `/sim`) —
  поиск пользователя по токену через `UserStorage`. Прежний хардкод токена `123` убран.
- `FlightMissionControl.landing`: на каждой посадке рейса пользователя (`mission.getUserId() > 0`) локация его персоны
  (`Persons.byUserId`) становится «аэропорт посадки». Если у пользователя нет персоны, в лог пишется warning.

## Код

`net.simforge.airways2.app.userstorage`: `User` (id, token, personId, vatsimCid), `UserStorage`, временный `LegacyUsersImport`.

## /flight-dashboard/status: секция pilot

В ответе секция `pilot` (раньше называлась `user`): то, что нужно дашбордам про пилота пользователя. Это результат сверки аэропорта, в котором
пилот загрузился (`sim.airportIcao`), с аэропортом персоны пользователя (`User.personId`): `state`, `expectedAirport`, `currentAirport`. Анкетные данные
пилота (инициалы, аватар, деньги и т.п.) сюда не входят, они в `GET /pilot`. Если у пользователя нет персоны или персона не в аэропорту, ограничений нет:

| `pilot.state` | Когда |
|---|---|
| `OK` | у пользователя нет персоны, либо идёт рейс (`sim.flightMissionId != null` или у пользователя есть начатый и не законченный рейс, персона тогда `OnDuty`, это нормально), либо персона `Idle` в аэропорту и аэропорты совпали, либо персона не в аэропорту (ограничений нет) |
| `WRONG_AIRPORT` | персона `Idle`, пилот на земле в аэропорту, не совпал с аэропортом персоны |
| `UNKNOWN` | трекер не подключён, пилот в воздухе или на земле вне аэропорта |
| `PERSON_NOT_IDLE` | персона пользователя не `Idle` (например `Resting`, `Travelling`, или `OnDuty` без текущего рейса). Новое значение, веб-морда должна его показать и заблокировать действия |

`pilot.expectedAirport` (аэропорт персоны) и `pilot.currentAirport` (аэропорт, где пилот стоит сейчас)
заполняются всегда, когда значение известно, независимо от `state`.

Вординг сообщения формирует веб-морда по коду состояния; веб-морда блокирует действия при `WRONG_AIRPORT`.
Анкета пилота: `GET /pilot` (инициалы, состояние и локация персоны, баланс банковского счёта, позже аватар и т.п.), логбук: `GET /pilot/logbook`. Может ли пользователь бронировать BusyBirds: `GET /busy-birds/booking-status` (`canBook`, `problem`).
